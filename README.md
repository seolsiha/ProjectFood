# 食べ食べ アンパンサーチ 簡易仕様書

現在地の近くのレストランを、ホットペッパー グルメサーチAPIで検索するAndroidアプリです。

## アプリ名
食べ食べ アンパンサーチ(パンをモチーフにした名前です)

## 対象OS
Android 7.0(API 24)以上 / targetSdk 37
Galaxy SM-F711N(実機)で動作確認をしました。

## 開発環境 / 言語
Android Studio / Kotlin

## 開発期間
2026年9月11日 〜 2026年9月29日

※ 提出期限については、ご配慮をいただき延長を認めていただきました。ありがとうございました。

## コンセプト
起動したときから「食べ物のアプリ」だと分かる、かわいくて分かりやすい検索アプリを目指しました。

## 機能一覧
- スプラッシュ画面(食パンが左右に揺れます)
- 現在地の取得(GPS)
- 検索範囲の選択(300m〜3000m)
- 店舗の検索と一覧表示(店舗名・アクセス・サムネイル)
- 店舗詳細の表示(店舗名・住所・営業時間・画像)
- ホットペッパーのページを開く
- 地図(Googleマップ)で店舗の位置を見る
- 読み込み中の表示、エラーや0件のときのメッセージ

## 画面概要
1. スプラッシュ画面:黄色の背景で、食パンが揺れたあと検索画面へ移ります。
2. 検索条件入力画面:検索範囲を選んで「検索する」を押します。
3. 検索結果画面:近くの店舗が一覧で出ます。タップすると詳細へ移ります。
4. 店舗詳細画面:店舗の情報と、2つのボタン(ホットペッパー・地図)があります。

## 使用ライブラリ
Retrofit / Gson / OkHttp / Kotlin Coroutines / Glide / Navigation Component / RecyclerView / Google Play Services Location / Material Components

## 利用技術の選定理由
- Kotlin:Androidの標準的な言語で、勉強を始めていたため。
- Retrofit・Gson:APIの通信と、JSONの変換をまとめてできるため。
- Coroutines:通信中にアプリが止まらないようにするため。
- Glide:画像の表示が簡単にできるため。
- Navigation Component:3つの画面の移動を分かりやすく管理できるため。
- 生成AI:コードの作成やエラーの解決の補助として使いました。動かして確認しながら、内容を理解するようにしました。

## こだわったポイント
- アプリ全体:ポイントをつけたくて、スプラッシュ画面に食パンが揺れるアニメーションを入れました。
- アイコン:最初に目に入る部分で、使う人が中身を想像できるところなので、ランチャーアイコンから力を入れたいと思い、開発の前に作り方を自分で勉強しました。グルメアプリに見えるように、食べ物のデザインにしました。(参考:https://www.flaticon.com/search?word=food )
- APIキー:コードに直接書かず、`local.properties` に保存してGitに上がらないようにしました。

## デザイン面でこだわったポイント
- 黄色を中心に色をそろえました。
- 黄色の上では白い文字が見づらかったので、濃い茶色にしました。
- ボタンやヘッダーを丸くして、やさしい雰囲気にしました。

## 技術面でアドバイスがほしいポイント
- ViewModelを使った画面と通信処理の分け方(今はFragmentの中で通信しています)
- 検索結果が多いときの、ページングのやり方

## 動作確認について
ホットペッパーAPIは日本の店舗だけが対象のため、韓国にいる私の現在地では検索結果が0件になります。開発中は一時的に東京駅の緯度・経度を入れて、「検索 → 一覧 → 詳細 → 地図」の流れを確認しました。提出版は、現在地(GPS)を使うコードに戻しています。日本で実行するか、エミュレータの位置を日本にすると結果が表示されます。

## ビルド方法
APIキーはリポジトリに入れていません。
1. `local.properties` に次の1行を追加します。
   `HOTPEPPER_API_KEY=(ご自身のAPIキー)`
2. Gradle Sync をして、ビルド・実行します。

## 学んだこと
アプリ開発は初めてで、最初は3つの画面(検索条件入力、検索結果、店舗詳細)をどう作り始めればよいのかも分からず、たくさん迷いました。
途中で、店舗の位置が地図に表示されない問題があり、緯度・経度の値を変えたり、東京駅の座標を入れたり、地図を開く方法を変えたりして、いろいろ試しました。
通信のログを見て原因を探す方法や、ファイルを置く場所の大切さなど、一つずつ学べたと思います。

## 自己評価
アプリ開発が初めてで、分からないことがほとんどでした。勉強を始めたばかりの時期に大きな手術が入り、準備の時間が十分に取れなかったのですが、必須の3画面を最後まで動く形にできたことは良かったと思います。
足りない点は、コードの整理(ViewModelなど)、ページング、例外的なデータへの対応です。今後は、これらを勉強して、少しずつ改善していきたいです。
